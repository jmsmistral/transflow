# Local planning services

T046–T051 provide shared planning and acceptance services. T054 exposes public
`plan` and `why` adapters; `build`, dispatch and worker execution remain later tasks. The contributor `planning_probe` example exercises these services;
it is not an installed command.

`tf_plan::scope::Graph::validated` requires the complete matching structural
certificate. Full considers only relevant eligible ancestors; selected orders
explicit producers; between intersects reachable paths after explicit barriers.
Every selected consumer retains every alias, including validation and side inputs.
Nested boundaries stop traversal. Imported/foreign identities cannot become
producers. Named off-branch bindings and exact pins remain reads; contradictory
same-branch producer pins fail. Explicit boundary reads may start a bounded path
without authorizing their upstream producers.

`tf_plan::refresh::decide` uses one captured UTC microsecond clock. Always sources
execute whenever eligible. Positive TTL seconds become checked microseconds; due
means age is greater than or equal to the TTL. Explicit targets refresh sources.
Manual sources require an explicit target or relevant refresh request, including
under force. Force bypasses TTL/cache decisions inside the scope and never changes
checks, import ownership or publication guards. Current TTL sources become exact
read boundaries. Resource/check policies remain frozen in the captured declarations
and configuration.

`transflow::build_plan::prepare` retains ownership on a blocking worker while it
verifies the managed environment, captures source and imports the complete graph.
It allocates proposed dataset IDs once, rebinds discovery against that additive
registry overlay, normalizes typed parameter overrides and selects the scope.
Parameters are keyed by exact dataset reference and parameter name. Unknown or
out-of-scope references/types fail. Symbolic parent inputs require no old head.
Read boundaries acquire leases before strict Parquet verification. The saved draft
includes exact versions, all earlier fallback absence guards, output generations,
branch lifecycle revisions, environment, source, registry bytes, policies and
parameters. Its default expiry is fifteen minutes. Only runtime capture/draft/lease
state changes; it creates no data branches or registered dataset rows and calls no
producer function. Failed preparation leases expire naturally.

`accept` loads the original record, verifies its digest and captured bytes, and
revalidates the retained discovery without importing a changed checkout. Source,
registry, environment, branch/head or lease changes cause an explicit refusal.
The recovery-journal registry service commits the saved additive IDs before
execution. If subsequent acceptance fails, those identities remain registered and
unbuilt. Retrying the same unchanged draft can recognize its exact already-written
replacement; arbitrary registry edits still conflict. A single SQLite transaction
creates any absent output branch, immutable source/policy/replay evidence, jobs,
build and all write reservations, or rolls back all of those changes. Input leases
are promoted to build kind with a one-hour initial lifetime; the later executor
must renew them and use the accepted capture and bindings. Competing reservations
return a refusal without partially reserving outputs; dispatch/queue policy is
later execution work. No producer is launched by acceptance.

`tf_catalog::compute::finalize` requires a matching structural certificate,
verified capture and all exact per-alias versions. It hashes conservative helper,
SQL/resource and dependency-lock file content, stable identities, observed installed
environment, normalized declarations/checks/parameters, writer policy, declared
secret-version identifiers and an explicit evaluation clock when applicable.
Missing parents defer the key. Compute and check/evaluator fingerprints are
separate; source capture UUIDs are not compute inputs. Registry bytes, check display
names/descriptions, lineage layout and operational time/memory/admission/preview
settings are excluded explicitly. There is no recursive removal of user keys.
Source comments/docstrings can conservatively invalidate code. A deterministic
cache declaration is an author promise, not certification of hidden external I/O.

T054 adds [public inspection](INSPECTION.md), shared Git-ref capture, typed CLI
parameter normalization and saved timeout precedence. Branch selection follows the
shared explicit/Git/default rule. Provider replica resolution and execution remain
later work. Boundary reads use available-head policy with recorded fallback
evidence and explicit unknown-currentness warnings. Require-current refuses stale
or unassessable boundaries without hidden execution.
Installed applications will not need the specification repository.

[T051 cache preparation and adoption](../tf-store/CACHE.md) finalize child keys only
after in-build parents bind and reuse retained versions/checks under guarded heads.
